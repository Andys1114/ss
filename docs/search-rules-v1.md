# 搜索规则存储规范 v1

项目：跨平台学术检索快捷工具  
规范日期：2026-10-17  
文件格式版本：`schemaVersion: 1`（已采用，2026-10-17 开始实现）

已确认：一个网站可有多条具名搜索规则；验证状态仅作提示；每个输入字段对应一个查询参数，复杂检索式由用户手动填写。规则由维护者通过公共云端来源统一分发，客户端只读，不提供个人规则同步或本地自定义；更新失败时继续使用最近一次有效规则。

维护者直接编辑 JSON，校验后发布。客户端启动时后台检查更新，同时提供手动检查入口；发现新版本后提示，由用户点击应用。安装包附带公共规则快照，首次离线启动也可使用。

默认托管地址为 `https://rule.andys1114.cc.cd/search-rules.json`，通过构建期 `VITE_RULES_URL` 配置；规则数据结构和客户端行为不依赖特定托管平台。

## 1. 维护者添加网站时先区分入口和搜索规则

如果尚未确认某个网站支持 URL 参数搜索，只保存名称、主页和分类，并将 `searchRules` 设为空数组 `[]`。应用提供官方入口，不展示虚构的搜索字段。

如果已知搜索地址和参数，可以配置“基础 URL + 固定参数 + 输入字段映射”。用户手动输入条件后，应用生成、预览和复制 URL；用户点击搜索后才交给系统默认浏览器打开。

一个网站可以包含“搜论文”“搜作者”等多条具名搜索规则，网站仍是收藏和导航对象。每次由用户选择一条规则执行。

初版每个输入字段对应一个查询参数，不自动把多个字段组合为同一个表达式；复杂检索式由用户手动填写在文本框中。初版不使用任意字符串替换模板，不执行规则中的脚本，也不支持 POST 表单、路径占位符或多步骤网页操作。

### 共享搜索内容与网站按钮

界面顶部使用一份共享搜索内容，映射到当前规则按数组顺序出现的第一个 `type: "text"` 字段。维护者应将关键词或完整检索式字段放在第一个文本字段的位置；没有文本字段时不传入共享内容。共享框的当前值始终作为明确输入，留空时不自动恢复该字段的默认值。

其他字段显示在对应网站的“其他条件”中，按网站 ID 和规则 ID 分别保留输入及默认值。切换网站、检索方式、筛选、收藏或预览都不清空共享内容；也不自动改写检索式以适配网站语法。用户应自行检查检索式是否适合目标网站。

点击网站主按钮立即构造并打开该网站的链接；眼睛按钮按需打开预览弹窗，复制使用同一构造逻辑。主界面不常驻链接预览或底部工具栏，设置入口位于顶部。入口型网站仅打开配置的主页，不携带搜索内容。清空共享内容由用户显式操作；应用新规则集时仍遵循下文的清空确认流程。

## 2. 公共规则与个人状态分开保存

维护者统一新增、修改和发布网站及搜索规则。客户端从公共云端来源读取规则，不需要用户账号，不上传个人规则，也不提供新增、编辑或导入任意规则的界面。用户仍可在已有规则的表单中手动填写检索条件。

这一决定取代最初“用户自行添加规则”的要求。规则维护移至发布端；客户端保留只读 JSON 导出，用于查看和备份，不将导出文件作为可编辑配置重新导入。

| 数据 | 职责 | 保存位置 |
| --- | --- | --- |
| 公共规则集 | 网站、搜索规则和验证记录的唯一发布来源，采用下文 JSON 格式 | 云端；托管方式待定 |
| 内置规则快照 | 随安装包附带的公共规则集版本，首次离线或没有有效缓存时使用 | 应用资源目录 |
| 最近一次有效规则缓存 | 更新失败时继续提供网站导航、URL 构造和手动打开功能 | 应用专用本地配置目录 |
| 个人状态 | 收藏、排序、最近使用、主题、窗口设置 | 本地个人状态文件 |

缓存是已接受公共规则集的只读本地副本，不是用户可编辑的规则分支。客户端完整校验下载的新规则后，将其作为待应用更新；用户点击应用时才整体替换有效规则集。下载失败、内容无效或版本不兼容时，保留旧规则并提示更新状态。替换写入不得破坏原有效副本。

Windows 和 macOS 使用各自的平台配置目录，具体目录由后续应用标识和 Tauri 路径接口确定，不写死盘符或用户名。规则可以离线读取、构造和复制 URL；目标数据库是否能访问仍取决于网络及网站自身条件。

关键词和筛选条件只用于本地 URL 构造，不上传到规则分发端；用户打开链接后，条件随 URL 交给目标网站。规则文件和规则导出不包含最近输入、登录信息、Cookie、访问令牌或个人状态。

个人状态通过网站 ID 关联公共规则，不通过网站名称关联。规则集更新不覆盖个人状态。本规范不定义个人状态文件的完整结构。

## 3. 完整 JSON 示例

以下域名和搜索参数仅用于演示格式，不代表真实数据库的搜索接口。第一个网站是纯入口；第二个网站是尚待验证的搜索规则草稿。

```json
{
  "format": "academic-search-rules",
  "schemaVersion": 1,
  "revision": 1,
  "sites": [
    {
      "id": "example-entry",
      "name": "示例网站入口",
      "homepage": "https://example.com/",
      "category": "学术数据库",
      "notes": "尚未确认 URL 搜索能力，仅提供入口",
      "searchRules": []
    },
    {
      "id": "example-library",
      "name": "示例学术检索站",
      "homepage": "https://example.org/",
      "category": "学术数据库",
      "notes": "仅用于说明规则结构",
      "searchRules": [
        {
          "id": "article-search",
          "name": "搜论文",
          "mode": "query",
          "baseUrl": "https://example.org/search",
          "fixedParams": [
            {
              "name": "scope",
              "value": "articles"
            }
          ],
          "fields": [
            {
              "id": "keyword",
              "label": "关键词",
              "param": "q",
              "type": "text",
              "required": true,
              "defaultValue": "",
              "placeholder": "手动输入检索词"
            },
            {
              "id": "start-date",
              "label": "开始日期",
              "param": "from",
              "type": "date",
              "required": false,
              "defaultValue": ""
            },
            {
              "id": "sort",
              "label": "排序方式",
              "param": "sort",
              "type": "select",
              "required": false,
              "defaultValue": "relevance",
              "options": [
                {
                  "label": "相关性",
                  "value": "relevance"
                },
                {
                  "label": "最新",
                  "value": "newest"
                }
              ]
            }
          ],
          "verification": {
            "status": "unverified"
          }
        },
        {
          "id": "author-search",
          "name": "搜作者",
          "mode": "query",
          "baseUrl": "https://example.org/authors",
          "fixedParams": [],
          "fields": [
            {
              "id": "author",
              "label": "作者姓名",
              "param": "q",
              "type": "text",
              "required": true,
              "defaultValue": ""
            }
          ],
          "verification": {
            "status": "unverified"
          }
        }
      ]
    }
  ]
}
```

文件使用 UTF-8 编码和标准 JSON，不允许注释、尾随逗号或重复对象键。导出时使用两空格缩进。

## 4. 字段定义

### 4.1 文件顶层

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `format` | 字符串 | 是 | 固定为 `academic-search-rules` |
| `schemaVersion` | 整数 | 是 | 本版固定为 `1`，标识数据结构版本 |
| `revision` | 整数 | 是 | 正的安全整数，标识公共规则内容的发布版本；每次发布严格递增 |
| `sites` | 网站数组 | 是 | 可以为空；网站 `id` 在文件内唯一 |

### 4.2 网站

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `id` | 字符串 | 是 | 非空、稳定的标识；重命名网站时保持不变 |
| `name` | 字符串 | 是 | 非空的显示名称 |
| `homepage` | 字符串 | 是 | 完整的 HTTP/HTTPS URL |
| `category` | 字符串 | 是 | 非空；初版每个网站一个分类 |
| `notes` | 字符串 | 否 | 纯文本备注，可为空 |
| `searchRules` | 搜索规则数组 | 是 | 可以为空；空数组表示仅提供入口；规则 `id` 在当前网站内唯一 |

维护者为新网站分配稳定且唯一的 ID，可以使用 UUID 或可读标识。不要根据名称变化重新生成 ID；已移除网站的 ID 不得分配给另一个无关网站。

`sites` 的数组顺序作为初始展示顺序。用户调整后的顺序放在个人状态文件中，不改写规则内容。

### 4.3 搜索规则

每条规则具有独立的稳定 ID 和显示名称。改规则名称时保留 ID；字段 ID 和参数冲突只在各自规则内校验，不同规则可使用相同字段 ID 或参数名。

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `id` | 字符串 | 是 | 非空，在当前网站内唯一；重命名规则时保持不变 |
| `name` | 字符串 | 是 | 非空，例如“搜论文”或“搜作者” |
| `mode` | 字符串 | 是 | 本版只允许 `query` |
| `baseUrl` | 字符串 | 是 | 完整 HTTP/HTTPS URL，可包含路径，不包含查询部分和片段 |
| `fixedParams` | 固定参数数组 | 是 | 可以为空，始终加入 URL |
| `fields` | 输入字段数组 | 是 | 可以为空；数组顺序即表单顺序 |
| `verification` | 验证记录 | 是 | 定义见第 6 节 |

基础地址中的已有查询参数应拆入 `fixedParams`。纯入口统一使用 `searchRules: []`，不增加另一种入口模式。

### 4.4 固定参数

每项包含两个必填字符串：`name` 和 `value`。`name` 不能为空，`value` 可以为空。

固定参数使用数组，以保留同名参数和顺序。例如同一个名称的两个值应分别保存为两项，不能用逗号拼接替代。

固定参数与动态字段不能使用相同的参数名，避免出现覆盖或含义不明确的 URL。

### 4.5 输入字段

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `id` | 字符串 | 是 | 非空，在当前规则内唯一 |
| `label` | 字符串 | 是 | 非空的表单标签 |
| `param` | 字符串 | 是 | 非空的目标查询参数名，在动态字段间唯一 |
| `type` | 字符串 | 是 | `text`、`date` 或 `select` |
| `required` | 布尔值 | 是 | 是否必须填写 |
| `defaultValue` | 字符串 | 否 | 未提供输入值时使用；省略时按空字符串处理 |
| `placeholder` | 字符串 | 否 | 输入提示，不作为实际值提交 |
| `options` | 选项数组 | 条件必填 | 仅 `select` 使用，且必须非空 |

`id` 是应用内部标识；`param` 是网站接收的参数名。例如不同网站的 `keyword` 字段可以分别映射到 `q`、`query` 或 `term`。

所有输入值和默认值均为字符串，不使用 `null`、数字或日期对象：

- `text`：文本原值，不自动提取、补充或改写关键词。
- `date`：空字符串或有效的公历日期 `YYYY-MM-DD`，不附带时间与时区。日期格式化和网站参数含义必须逐站确认；其他日期格式可先使用文本字段。
- `select`：每个选项包含非空的 `label` 和 `value` 字符串，选项值在字段内唯一。非空默认值和实际值必须属于选项。可选字段可以清空，表示不提交参数。

必填字段允许空默认值，用于要求用户在执行前填写。日期范围的先后关系和跨字段组合校验不属于 v1 通用格式；不能因日期控件存在就认定网站支持日期筛选。

## 5. URL 构造与空值处理

按以下顺序生成 URL：

1. 校验规则和本次表单输入。
2. 解析 `baseUrl`。
3. 按顺序加入所有固定参数，包括空值参数和同名参数。
4. 按字段顺序解析动态值并加入非空参数。
5. 生成最终 URL，供预览、复制和用户确认后打开。

动态值的确定方式：

| 本次输入状态 | 处理 |
| --- | --- |
| 没有该字段的输入值 | 使用 `defaultValue`，未定义则为空 |
| 用户主动清空字段 | 保持为空，不重新套用默认值 |
| 可选字段为空 | 省略整个查询参数 |
| 必填字段为空 | 显示字段错误，禁止执行搜索 |

空字符串以及仅包含空白的文本视为空；非空文本保留用户输入，不额外裁剪或改写。默认值只解决“未提供输入”，不覆盖用户明确输入的空值。配置保存和规则导出均不写入当前表单值。

编码约定：

- 配置保存未编码的原始参数名和值。
- 构造时使用 URL 与查询参数 API 逐项编码，不手工拼接 `&`、`=`。
- 不对整条 URL 再执行一次编码，不预先编码中文、空格、`&`、`+` 或 `%`。
- 查询参数名区分大小写；不合并不同大小写的名称。
- 预览、复制和打开使用同一个构造结果；输入变化后立即使旧结果失效，不能误开上一次的链接。

使用示例中的“搜论文”规则，输入 `机器学习 & 教育`，留空开始日期，保持默认排序，最终 URL 为：

```text
https://example.org/search?scope=articles&q=%E6%9C%BA%E5%99%A8%E5%AD%A6%E4%B9%A0+%26+%E6%95%99%E8%82%B2&sort=relevance
```

其中空格采用查询参数 API 的 `+` 编码，用户输入的 `&` 编码为 `%26`，不会产生额外参数；`from` 被省略。

## 6. 验证状态只作提示，不限制手动搜索

维护中的未验证规则记录：

```json
{
  "status": "unverified"
}
```

经过验证后，记录实际验证日期、方式和结果。以下内容仅演示记录结构，不是对示例站点的验证结论：

```json
{
  "status": "verified",
  "checkedAt": "2026-10-17",
  "method": "manual",
  "notes": "已手动确认关键词和排序条件实际生效"
}
```

| 字段 | 规则 |
| --- | --- |
| `status` | 必填，`unverified` 或 `verified` |
| `checkedAt` | `verified` 时必填，有效日期 `YYYY-MM-DD` |
| `method` | `verified` 时必填，`manual` 或 `official-docs` |
| `notes` | 可选，纯文本，说明验证的字段和限制 |
| `referenceUrl` | 可选，HTTP/HTTPS 文档链接；`official-docs` 时必填 |

交互约定：

- `searchRules: []`：提供“打开官网”。
- `unverified`：显示“未经验证”提示；规则和输入校验通过后，允许预览、复制和手动搜索，不要求先完成验证操作。
- `verified`：显示验证记录，仍由用户手动触发搜索。
- 状态仅说明接口有效性的验证记录；不替代规则格式、URL 和输入值校验。
- 维护者修改 `mode`、`baseUrl`、`fixedParams` 或 `fields` 后，须将该规则状态改为 `unverified` 并清除旧验证记录；修改网站名称、规则名称、分类和备注不影响验证状态。客户端不编辑这些记录。

页面能打开不等于规则有效。手动验证需要确认关键词和所配置条件确实生效。官方文档验证需要文档明确说明该地址及参数，不能根据地址外观推测。

公共规则集正式收录搜索接口前，由维护者确认接口和参数有效；尚未确认搜索能力的网站只提供官方入口。已有规则因接口变化待复核时可以标记为 `unverified`，由界面提示用户，不强制禁止手动使用。验证记录由维护者提供，不代表客户端刚刚重新测试过；界面允许查看依据。

## 7. 云端规则接收、校验与只读导出

### 接收前完整校验

维护者准备发布文件以及客户端接收云端更新时，均须完整校验规则。发现错误时不部分写入，并提示错误位置，例如 `sites[1].searchRules[0].fields[2].defaultValue`。

校验至少包括：

- JSON 语法、格式标识、版本及字段类型。
- 必填值、网站 ID、规则 ID、字段 ID、参数名和选项值的唯一性要求。
- HTTP/HTTPS 地址、基础地址无查询部分和片段。
- 固定参数与动态参数不存在冲突。
- 字段类型、选项和默认值有效。
- 验证记录满足其状态对应的要求。

不接受非 HTTP/HTTPS 链接、可执行表达式或脚本规则。名称、标签和备注一律作为纯文本显示，不作为 HTML 渲染。v1 中出现未定义字段时提示错误，不静默丢弃可能影响规则含义的内容。

### 整体替换，不合并个人规则

- 同一规则集内网站 ID 重复或同一网站内规则 ID 重复：拒绝整份更新。
- 云端新版本整体替换旧规则集，不执行“替换、跳过或另存”的逐项导入流程。
- 网站和规则通过稳定 ID 识别；名称相同不代表同一对象，重命名不改变其身份。
- 缓存缺失、损坏或不兼容时使用随安装包附带的有效规则快照，并显示当前来源。
- 启动时加载有效缓存与内置快照中 `revision` 较高的一份；待应用更新不参与启动选择。
- 没有任何有效规则来源时显示可恢复的加载错误和手动检查入口，不用空列表冒充加载成功。

### 格式版本与导出

- 当前只接受 `schemaVersion: 1`。
- 高于当前支持版本：提示升级应用，不猜测解析，继续使用兼容的有效缓存。
- 后续版本需要显式迁移，不通过改字段含义兼容旧数据。
- `schemaVersion` 标识结构，`revision` 标识规则内容的发布版本，两者独立。
- 同一公共规则来源内，远端 `revision` 大于当前版本才提示新版本；相同表示无需更新，较低版本不覆盖当前规则。
- 维护者修复或回退内容时仍发布更高的 `revision`，不重复使用旧版本号。
- 全量和选中网站的只读导出都保留顶层封装；选中导出只缩小 `sites` 数组。
- 导出保留 ID、字段顺序、固定参数顺序及验证记录，不混入个人状态或当前表单值。

### 维护者编辑与发布

1. 编辑公共规则 JSON，保留既有网站与规则 ID。
2. 按本规范校验结构、参数和验证记录，并逐站确认新增搜索接口；未确认的新增网站只保留主页。
3. 将 `revision` 增加到大于所有既有发布版本的整数。
4. 将完整有效文件发布到公共规则地址；不分批发布单个网站。具体托管及发布操作在部署阶段确定。
5. 应用打包时，从维护的公共规则集中选取一份有效版本作为内置快照。

不建设专门规则管理界面，不在客户端加入个人编辑或文件导入入口。

### 启动检查、手动检查与应用更新

- 启动先加载本地有效规则立即展示，再在后台检查云端，不等待下载后才显示网站列表。
- 设置提供“检查规则更新”，与启动检查使用同一套下载和校验流程。检查进行中不重复启动并发检查。
- 发现并校验更高版本后显示“发现规则更新”，包含当前版本、待应用版本和“应用更新”操作。下载成功不等于已经应用。
- 用户未点击应用时，当前规则、表单和 URL 预览保持不变。未确认的更新不能在下次启动时自动变成有效缓存；以后仍需提示用户应用。
- 用户点击应用且存在已填写内容时，先提示将重新加载表单并清空当前输入；取消则保留旧版本和输入。
- 确认后完整写入新有效缓存，再切换规则集并重建表单、使旧 URL 预览失效；不把旧输入套入新规则。写入失败时保留原有效缓存与当前使用状态。
- 更新不覆盖个人收藏、排序、最近使用和窗口设置。被移除的网站不再显示为可用入口，但保留其个人关联；同一网站 ID 恢复后可重新关联。
- 检查或更新失败时提示原因，保留当前可用来源，并允许手动重试。
- 此流程更新的是规则数据，不是应用程序本身，不触发安装包升级。

## 8. 实现时的关键验收场景

1. 纯入口网站没有搜索表单，能由用户点击打开主页。
2. 中文、空格、`&`、`+`、`%` 正确编码且不被二次编码。
3. 固定参数始终保留，同名固定参数不会丢失。
4. 可选字段留空不生成参数；必填字段留空不能执行搜索。
5. 默认值只在缺少输入时生效，清空字段后不自动恢复。
6. 非法日期、选项外的值和冲突参数能定位到具体字段。
7. 预览、复制和实际打开的 URL 一致，不使用旧输入产生的结果。
8. 未验证规则有明显提示但可手动搜索；修改一条规则的检索行为后，仅将该规则的验证状态重置，不阻止使用。
9. 云端规则完整校验后等待用户点击应用，再整体替换；下载失败、格式错误或版本不兼容时，保留当前有效规则并提示状态。
10. 规则导出不包含收藏、窗口设置、检索输入或登录凭据。
11. 一个网站内可切换“搜论文”和“搜作者”，字段、URL 和验证记录相互独立；网站收藏不重复。
12. 复杂检索式原样作为一个字段的值编码，不自动拆分或组合。
13. 客户端没有新增、修改、任意文件导入规则的入口；公共规则更新不覆盖收藏和窗口设置。
14. 有效规则可离线读取、构造和复制 URL；规则分发请求不包含关键词、筛选条件或个人状态。
15. 启动后台检查和手动检查均可发现更新；未确认的新规则在本次会话及下次启动时都不自动生效。
16. 应用更新需确认清空已有输入，取消不影响当前表单；确认后不再使用旧 URL 预览。
17. 首次断网或缓存损坏时使用有效内置快照，界面显示实际使用的规则来源和内容版本。
18. 相同或较低 `revision` 不覆盖当前规则；写入失败时仍能继续使用原版本。

## 9. 人工检索边界

网站、关键词和筛选条件全部由用户手动选择或输入。软件只整理入口、构造 URL，并在用户点击后打开链接。

不读取考试平台或其他网页中的题目，不使用 AI 解析题目或自动提取关键词，不爬取检索结果，不自动进入网站执行多步骤操作，不匹配答案，也不自动填写或提交考试答案。
